# 投标作为平台子模块的接入方案

2026-10-06，T39/T40。用户在同窗口页面＋原引擎后台方案说明后回复“继续工作”，T40按平台内子模块要求实施；不记录为已选异步选择框或已签收。原独立运行环境继续保留，界面已经接入平台同一主窗口，成品检查见T40日志。

## 当前可用方式与已发现问题

T38复制了原框架和业务，平台入口启动独立Electron41模块并隐藏工作台。它具备操作能力，但窗口启动被windowsHide参数隐藏，用户无法看到。T39恢复现有窗口并修正启动、最小化恢复、返回平台、失败恢复，统一品牌/窗口位置/模块导航。

这解决了打不开及入口体验，仍是两个原生窗口切换；不能称为投标页面已经嵌入同一个主窗口。用户对严格同窗口的要求已提请澄清，不把独立运行环境的历史批准解释成界面形式的签收。

## T40已实施的同窗口结构

保持平台Electron44、原框架Electron41，两者分工如下：

| 部分 | 工作 | 用户看到的界面 |
| --- | --- | --- |
| 平台主窗口 | 首页、统一导航及原易标投标页面 | 始终一扇EngiSpace窗口 |
| 原投标后台引擎 | 原SQLite存储、解析、Agent、Word导出 | 后台运行，不显示另一扇业务窗口 |
| 本机通信桥接 | 转发原页面请求、结果、进度、取消及文件对话框 | 点击后得到正常操作结果 |

界面使用主窗口中的WebContentsView承载原前端，避免重写七步业务。后台保持原运行环境，避免在44中加载不兼容的SQLite库。通信仅用本机进程通道，不新增互联网接口，不上传统计。

### 已取得的可行性证据

G盘临时原型实际启动Electron41，通过父子进程IPC收到请求并运行better-sqlite3内存数据库SELECT 1，回复成功，退出0，stderr空。证据artifacts/runs/t39/engine-ipc-probe.json。这证明原环境可以作为本机引擎被调用；该原型为T39历史证据；T40已完成原业务桥接，13项真实源码检查通过，SQLite/Word/二进制资源/生命周期均有证据，成品与人工签收另记T40。

### 实施顺序与验收

1. 修复当前入口并交付能显示的版本，保留原资料及旧稿；补原生窗口可见性检查。
2. T40按用户继续指令记录内部桥接契约：只转发现有白名单IPC，区分请求/结果/进度/原生文件对话框/取消/退出；不开放任意代码执行或裸文件操作接口。
3. 主窗口加入投标内容视图，原后台引擎改为隐藏运行；文件选择、导出对话框由平台显示，私有图片由既有受限资源协议提供。返回首页复用原保存/任务离开保护，不能直接隐藏正在保存的输入。
4. 用同一个主窗口实际走首页→导入资料→编辑/保存→Word导出→返回首页→重新进入；核验窗口句柄不变、后台无多余可见窗口、旧数据保留、进度/取消/失败可恢复、断开引擎不会让平台消失。

这部分需要新增桌面内部通信契约和生命周期管理，原预加载API/资源协议/图像预览/原生对话框都要验证；不能用一个iframe或仅复制UI声称接好。共享代码只在投标worktree调整，不把未验收的设计说明分支一起合入，也不改CAD接口。
