# 旧设计说明资料整理交接词（工作底稿）

用途：把用户一次性提供的各版本、各专业设计说明整理为桌面端 B2/B3 可审查的内容候选与项目字段清单。**本任务只整理，不写入产品标准库，也不建立数据库或修改代码。**现有 25 个章节 ID 见 [内容清单](CONTENT_INVENTORY.md)；产品流程见 [PRD](PRD.md) 第 3 章。旧项目文字不是现行规范或通用结论的证明。

## 建议分四步

1. **清点资料**：逐文件记专业、项目类型、日期/版次、格式、哈希、能否读取及保密/转载状态。扫描件可 OCR，但标明 OCR；无法读取的文件列出，不静默跳过。
2. **拆成最小可复用句段**：按现有章节 ID 归类；固定文字、只在特定条件下用的文字、单项目事实、规范引用分别标记。相同表述合并来源；不同版本冲突并列保留，不用出现次数决定正确性。
3. **抽出项目字段**：把工程名、地点、面积、等级、材料、抗震参数等随项目变化的值改成明确占位符，记录字段类型、单位、归属层级、适用条件与例值。例值不得变成默认值；非结构专业不得因此出现结构专属输入。
4. **核对并交接**：每条候选都能回到原文件具体位置；列出冲突、疑似过期规范、缺来源、权限和待用户决定项。先交内容候选，由项目开发 Agent 和用户核定后再进入正式库。

## 可直接发给资料整理 Agent 的提示词

> 你负责整理设计说明资料，暂不开发程序。用户会一次性给你结构、建筑、给排水、电气、暖通及其他专业的多版本 DOCX/PDF 等文件。请按批次处理全部文件，不能因为上下文或时间限制只处理前几份；必要时保存进度并接续，最后列明已处理与未处理文件。
>
> 先读项目的 `AGENTS.md`、`docs/CONTENT_INVENTORY.md`、`docs/PRD.md` 第 3 章、`docs/IMPLEMENTATION_PLAN.md` 的 B 阶段。若不能访问仓库，请让用户同时提供这四个文件。沿用现有 25 个章节 ID；对放不进去的内容单列建议，不自行改产品章节库。
>
> 请在 G 盘项目目录 `artifacts/content-handoff/` 交付以下文件（此目录不入公开 Git）：
>
> 1. `README.md`：处理方法、总文件数/已处理数/失败数、各专业覆盖、质量限制和如何复核。
> 2. `sources.csv`：每份源文件一个 `source_id`，包含原文件名、SHA-256、专业、项目/类型、日期或版次、格式、是否 OCR、提取状态、保密/转载状态。未知写“待核定”。
> 3. `clauses.jsonl`：每个可判断的句段一行 JSON，至少含 `id`、`discipline`、`section_id`、`kind`（固定/条件/单项目/不可用）、`original_text`、`candidate_template`、`applicability`、`field_ids`、`source_refs`（source_id 与页码/段落位置）、`variant_group`、`review_status`、`notes`。正文可保留内部原文，不能公开上传。条件句必须写清适用工程；规范引用标“待核定”，不宣称仍有效。
> 4. `project_fields.csv`：一行一个建议字段，至少含字段 ID、中文名称、层级（项目/专业/本份说明/章节）、类型、单位、可选值候选、何时必填、出现的章节 ID、来源、例值、是否敏感。多份说明中的不同项目值不得被合并成默认值。这里是**未来数据库的数据字典**，不用建库。
> 5. `coverage.md`：按现有 25 个章节 ID 列候选数、来源数、缺口；另列无法归类或建议新增的章节，不直接修改现有 ID。
> 6. `review_queue.md`：按优先级列冲突版本、过时风险、无来源、OCR 不清、可用/转载权限、字段定义分歧，以及你需要用户核定的少量问题。每项指向 `source_id` 和句段 ID。
>
> 抽取时把句子拆到能独立判断适用条件的程度。例如“建筑面积为 12345 平方米”应成为含 `{{project.building_area}}` 的候选和一个带平方米单位的项目字段；12345 只作原项目例值。若一个句段只适用于水池、框架或钢结构，条件必须写明。引用某规范的语句保持来源与版次，不凭旧说明认定该规范现行有效。
>
> 保留相似句的所有出处，合并重复候选；冲突的句子放同一 `variant_group`，不要自行挑选“最新版”或“最常见版”作为最终正文。每条候选先标“待核定”；用户的旧说明不等于已批准的全局标准。不要编造缺失文字，不要自动改写用户源文件，不要把私有源文件、客户/项目真实信息或交接包提交到公开仓库。
>
> 完成前检查：源文件数与清单一致；每条候选有可定位的原文出处；每个占位符在 `project_fields.csv` 有定义；`clauses.jsonl` 可逐行解析；25 个章节在覆盖表中全部出现；失败文件、冲突和未核定项均明确列出。最后把交接目录路径、文件数、候选句段数、字段数、最重要的待决问题简要报告给用户，供用户转交项目开发 Agent。

## 开发 Agent 接收规则

先检查交接包的完整性、来源与私密性，再同用户逐批核定可复用正文、条件和字段；核定前不写入正式内容库。B2 优先结构，B3 再按其他专业资料推进。项目字段的数据字典用于后续存储/界面设计讨论，**不自动改变当前共享协议**。
