## 3. 建议分类（先兼容旧路径）

| 类别 | 目标位置/策略 | Git |
| --- | --- | --- |
| 程序源码和构建定义 | 保留 src、tests、desktop（有此目录的分支）、schemas、scripts、build、packaging | 跟踪 |
| 标准及正式文档 | 保留 standards、docs；本方案、开发计划和日志入 docs | 仅公开/脱敏内容 |
| 外部参考源码 | local/references/项目名，记录上游 SHA 和许可，不嵌入 src | 忽略 |
| 业务原稿 | 新增资料收进 local/inputs/项目或日期；既有说明文件/content-library/private 先原位索引 | 忽略；迁移前核对许可/引用 |
| 设计参考 | 新资料放 local/design-reference；既有 Figma ZIP/截图先保留并建索引 | 原素材不默认公开 |
| 工作树 | 新增统一放 artifacts/worktrees/任务名；现有 *-worktree 原位登记 | 忽略；由 Git 管理 |
| 开发检查输出 | 新输出放 artifacts/runs/任务/日期；旧证据先索引 | 忽略 |
| 构建中间产物 | artifacts/build/任务；现有脚本输出路径在维护时逐步调整 | 忽略 |
| 软件试用与发行 | 当前 测试文件/设计说明客户端试用、CAD表格试用、CAD安装候选 保持入口；新标书放 测试文件/勘察设计投标试用 | 忽略；后续统一指向版本化交付区 |
| 历史归档 | local/archive/类别/任务日期；不将所有目录机械搬进 archive | 忽略 |
| 目录索引及迁移记录 | 公共规则 docs/PROJECT_ORGANIZATION_PLAN.md；具体路径/哈希 local/organization | 规则跟踪，私有清单忽略 |

不立即改名所有旧工作树和试用目录。P1 先通过索引让入口清楚，再按验证过的迁移清单处理。当前 T33 工作树仍为 artifacts/t33-bid-plan-worktree；后续新增采用统一规则，不为了美观再迁移一次。

## 5. 执行顺序与回退

1. 用户批准方案后重新检查 git status/worktree、文件变化和正在使用的程序；清理阶段先于标书开发。
2. 生成本机机器可读 action-manifest，逐项记录：原位置、目标位置或删除动作、理由、大小、哈希、保留副本、依赖引用和恢复方法。清单不是通配符删除脚本。
3. 对迁移项先复制到 G 盘目标、逐文件校验 SHA256、更新脚本/指南/目录索引；验证后再处理原副本。递归操作前校验解析后的绝对路径严格位于批准的项目目录，拒绝符号链接越界。
4. 对删除解压副本先验证对应 ZIP 可解压及文件相等；唯一/改动文件不删。保留 ZIP 的压缩归档不会额外复制一整套大型解压目录。
5. 只对已列明的精确路径执行动作，逐项写报告。活动 worktree 不能用普通文件夹剪切；未提交或忽略资料不依靠 Git 自动保护。
6. 核对原有客户端启动入口、源码构建路径、标准/资料库引用和当前候选清单；按改动运行必要的检查，不重做无关 CAD 宿主验收。
7. 交付整理前后容量、移动/删除/保留统计、失败项及恢复步骤；程序与文档变更按任务提交，私有清单留本机。通过后再进行 P2。

恢复方式：文件迁移按映射返回原位；解压副本从已校验 ZIP 恢复；构建目录重新构建；受跟踪的配置改动用 git revert 保留历史。不能把无法重建的私有文件归入「可再生成」。

## 6. 防止再次混乱

- 新任务开始登记唯一工作目录、分支、输出位置和当前可运行入口。
- 一个产品只标一个「当前候选」入口；版本包保留版本与提交号，避免靠「最终/最新/再试」判断。
- 交付时记录是否包含私有资料、是否可公开、保留原因；开发构建和用户试用区分开。
- 任务结束检查新增根目录杂项、未跟踪文件、临时目录和重复解压副本，先分类后清理。
- 删除看来源、用途、恢复能力和当前引用，不能只看名字/日期/扩展名；不直接操作 .git。
- 本轮规则先写入 T33 分支 AGENTS.md；用户批准后在整理阶段向活动分支串行同步，保留各分支已有规则，不用整文件覆盖。

**通过标准：找得到当前程序、原稿和证据；旧入口不失效；没有误删独有数据；新增参考和工作树均在 G 盘；清理结果可追溯且可恢复。**
