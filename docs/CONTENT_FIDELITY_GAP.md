# 设计说明成品差距与下一阶段建议

更新：2026-09-29。用户已在真实窗口确认 T26 可以生成并导出说明，但生成内容和格式与提供的原说明差距很大。此确认只证明编制和导出链路可用，不代表专业成品已通过。

## 已核对的差距

以用户提供的《结构设计说明（构筑物）.docx》为第一份基准：原文件有 8 个大章、167 个非空段落、7 张表；《结构设计说明（构筑物加框架）.docx》有 8 个大章、181 个非空段落、7 张表。当前 T26 水池模板自动装配 99 条、12 个 CH 主题章，水池＋框架为 125 条、15 个 CH 主题章。原文件主要依靠段落文字写章节和分项编号，并非 Word 内置自动编号；因此必须保存原段落顺序、编号层级及表格位置，不能仅按 CH 主题重排。

现行候选包的 1405 条有来源和字段追溯，适合做内容索引；它把原文拆成句子候选，并把条件句、项目事实、表格等单独标记。T26 为避免旧项目值与未核定内容误入新工程，自动排除了大量候选。这是生成初稿与原说明内容不齐的直接原因，不能据此认定原 DOCX 资料有问题。原资料中的具体取值与规范引用本身仍需工程和专业核定。

导出工作进程目前只创建标题、二级标题和普通段落，没有表格、分项编号及专用说明版式；当前 PRD 也把表格与 Word 视觉排版继承列为延期项。若目标变成与原说明同等完整的可编辑成品，需要扩展内容模型和 DOCX 导出规则。建议采用项目自己的版本化版式规则，重现章序、编号、表格和主要排版，不把原 Word 的每处直接格式当作运行时依赖。

## 建议顺序

1. **先做一份成品基准**：以构筑物（水池）原 DOCX 为目标，建立按原章节顺序组织的模板；每段标明固定文字、工程字段、条件文字、规范引用或表格，并保留原段落/表格来源位置。旧项目值只作提取证据，不作新工程默认值。
2. **扩展内容模型和导出器**：支持有序章节、分项编号、正文段落、固定表格块及适用条件；预览与 DOCX 使用同一结构。不能确定适用条件或缺工程值时明确待核定或阻断，不能悄悄删掉导致说明看似完整。
3. **以脱敏工程值生成对照稿**：逐章对比原文和新稿，记录保留、参数化、条件排除和待核定的每一项；检查表格、编号、章序、Word/WPS 可编辑性及现有 DOCX 解析器读回。版式以原说明的层级和密度为基准，允许项目统一样式，不要求逐页与旧 DOCX 像素一致。
4. 水池基准通过后复用模型完成框架、水池＋框架，再逐专业处理建筑、工艺、电气、暖通。钢结构和“其他”在取得主体来源前不宣称完整。

**集成建议**：T18 已获用户框架试用认可，可以独立按依赖顺序集成；T26 的自动装配代码应继续留在任务分支，先达到上述成品基准，再作为 B 阶段成果集成。旧项目私有 DOCX、候选包及对照测试结果继续留在 G 盘并由 Git 忽略。
