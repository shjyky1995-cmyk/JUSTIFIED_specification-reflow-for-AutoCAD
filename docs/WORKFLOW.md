# 开发与验收流程（定稿）

## 目标和交付阶段

首个目标：设计人员在工程里设好一次标准和单位后，用一个命令点一下说明位置，就把 Word 说明生成可编辑的 CAD 单行文字。程序负责识别正文、标题和编号，并自动换行、分栏续页。机构和个人标准仍可独立配置。当前多步提问只用于开发核对，不是正式操作。

按大阶段交付，原T编号继续用于追踪、日志和提交，不成为要求用户反复回复的关卡：

| 交付阶段 | 包含任务 | 阶段结果 |
|---|---|---|
| 1 排版引擎（下一阶段） | T07、T08 | 完整换行、内联编号、三图幅分栏与自动续页，通过相关核心测试 |
| 2 Word→CAD闭环 | T09、T10 | 复用已有Word解析，完成实体落图与操作入口，用户可实际演示 |
| 3 完善和正式验收 | T06剩余项、T11、T12 | 补齐真实字符/上下标/打印、性能、离线包和最终验收 |

T04/T05已有解析、T06已有测量基础，直接复用。开发需要的测量正确性不能跳过；完整打印验收后移，不反复阻塞主线。任何延期不免除正式发布要求，也不允许绕过生产缺值校验。

## 开始和执行

1. 检查Git状态，识别分支和未提交改动；不覆盖他人工作。
2. 读AGENTS、TASKS、ARCHITECTURE、WORKFLOW及NEXT_AGENT，再按需读任务日志最新记录、相关PRD条款和源码/接口/测试。无需反复全文读取所有历史或无关资料。
3. 确认本阶段目标、输入输出、范围、依赖与REQ/AC，简短告知后直接开发；正常接续不再问“要做哪一步”。
4. 阶段内自行安排实现、调试、针对性测试和提交。普通失败先自主修复；一个方法、一组测试或一次提交完成后继续推进，不因此结束本轮或要求用户确认。
5. 完成可验证成果后追加任务日志并提交，只暂存本任务文件。转入阶段内下一个T任务时串行更新分支/记录并继续，不需用户再发命令。相关检查通过即可，不重复无关全量检查。
6. 阶段目标完成，或出现下述中断条件时，更新TASKS及NEXT_AGENT，按固定模板交付。用户验收后的一句“继续下一步”进入下一大阶段。

阶段内部的小步只是实现和提交粒度，不是用户验收粒度。合理简化文档：日志追加事实，NEXT_AGENT在内部任务切换、阶段交付或中断时同步，不为每个微小改动另写一轮方案。

## 何时中断或讨论

- 阶段完成，交给用户需要的验收操作；无需人工操作则明确说明。
- 存在无法自主排除的阻塞、需要用户操作/补充关键事实，或额度/环境不足以继续；先保存已有成果和恢复位置。
- 改变产品范围、验收目标、共享协议、模块依赖、技术栈或重要业务规则：记录问题、影响、推荐方案，再集中讨论。已明确授权的变更不重复确认。
- 用户要求暂停或换Agent。

内部修复、必要测试、既定配置与普通实现选择不属于必须讨论的事项。禁止降低AutoCAD安全设置，不擅改源业务文件；不能因完成容易的小步而提前把整个阶段交还用户。

## 用户指令和验收

- “继续下一步/开始下一步”：先读NEXT_AGENT；有中断则恢复本阶段，有未解决报错则先修复；否则按记录进入下一大阶段并持续推进。
- “验收通过，继续下一步”：登记上次明确列出的人工检查结果，再接续。无人工项不强造CAD操作。
- 用户完成上一交付列明的观察检查后只说“继续下一步”，可以记录为这些检查的用户确认；不能编造数值、日志，也不代表延期打印等未做事项通过。确需提供的数据仍缺失时只追问对应项，先推进不依赖它的工作。
- “有问题”或收到报错：修复当前阶段，复测后重新交付。沉默不代表验收。

## 固定交付格式

每次阶段结束或中断都说明以下内容，允许合并表达，避免机械堆砌；操作详细，其余简短：

1. **完成了什么**：阶段成果、可用入口/文件；不要把草案当成已实现功能。
2. **检查结果**：通过/未做/失败项、提交号、实际合并及远程备份状态。
3. **你现在做什么、怎样算通过**：无需操作，或准确文件路径、入口/现有命令、步骤、预期结果及要反馈的内容；不能提供虚构命令。
4. **问题与未完成项**：影响、异常时如何反馈、延期验证；中断时写明已尝试什么和恢复位置。
5. **下一步谁做什么**：唯一下一大阶段或恢复动作；用户可直接回复“继续下一步”，不需要重新整理上下文。

## 文件和跨Agent接续

AGENTS保存长期规则；本文件保存固定流程；TASKS保存任务状态；NEXT_AGENT是唯一当前接续状态，可更新替换；devlog追加历史。最新用户要求优先，旧日志保留但不能复活过期流程。

NEXT_AGENT至少记录：当前交付阶段/任务和状态、分支/基线、成果证据、用户待办、失败/延期项、唯一下一阶段或恢复位置、允许范围和验收目标。接手者依据文件而非聊天记忆；本机local资料不假定其他电脑存在。

默认从已验收main开task/<编号>-<简称>分支，当前阶段允许从已提交T06基础串行继承；T07→T08继续记录依赖。未验收祖先不得随分支直接合main，依赖验收后顺序集成。阶段通过相关检查和必要验收后合并、打阶段标签并推送私有远程；未完成验收不得假合并/假发布。

中断前将本任务未完成改动提交为checkpoint（确有改动才提交），写清失败和精确下一动作，再更新交接；不得因额度不足标记完成。状态仍使用待开始/进行中/阻塞/待验收/完成，并区分代码检查、用户确认和真实宿主证据。
