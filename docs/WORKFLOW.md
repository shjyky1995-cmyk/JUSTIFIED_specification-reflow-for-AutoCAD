# 开发、验收与接续流程

## 先达成的目标

先完成可演示的最小 Word→CAD 闭环：选择支持的DOCX和标准/模板 → 识别段落、标题、编号 → 按真实文字宽度换行 → 分栏及续页 → 点选位置 → 生成可编辑DBText。保留多套个人/机构标准入口。

当前顺序：复用T04/T05解析和T06测量基础 → T07自动换行 → T08分栏续页 → T09落图 → T10操作闭环。每阶段拆成一个可独立检查的小任务。完整字符/上下标/打印核验及T11/T12在正式发布前补齐；演示和发布分开，不能跳过必要的缺值/错误阻断来制造演示成功。

## 文件分工与读取顺序

1. 执行git status，识别当前分支、未提交改动与可能的他人工作；不清理、不覆盖。
2. 阅读AGENTS.md、TASKS.md、ARCHITECTURE.md，再读本流程和NEXT_AGENT.md。
3. 读取当前/下一任务日志最新段落、相关PRD条款，以及将修改的源码/接口/测试；无需每次全文重读全部历史、所有技能或无关文件。
4. 确认小任务编号、输入输出、依赖、允许修改范围、REQ/AC与验收方式；简短告知用户后直接执行。正常接续不再次询问要做哪个任务。

AGENTS保存长期规则；本文件保存固定流程；TASKS保存阶段状态；NEXT_AGENT保存唯一当前接续状态（可更新替换）；devlog按时间追加证据和决策历史，不覆盖。用户新指令优先于旧文件，先同步受影响记录；文件间冲突按最新已确认日志核对，不能自行复活过期要求。NEXT_AGENT只管接续，不得覆盖PRD范围和已确认架构。

## 每个小任务的固定循环

1. **领取**：编号例如T07-01，归属T07；记录目标、输入输出、依赖、范围、验收点。状态改为进行中。普通实现自主决定；不得停在计划或只新增无用文档。
2. **开发**：实现本小任务所需最小完整代码，复用现有模块，不顺便重构或扩范围。一次只领一个小任务。
3. **检查**：先相关自动测试/构建和必要宿主检查；失败自行修复。代码检查、人工验收和延期验收分别记录。测试通过才声称通过，不用模拟结果冒充真实宿主结果。
4. **记录并提交**：补日志、阶段状态与NEXT_AGENT，再只暂存本任务文件提交；检查提交后状态。交付引用真实提交SHA。NEXT_AGENT用分支及git查询定位当前提交，不填写会自引用的未来SHA。
5. **交付**：按下方固定模板发结果。完成本小任务后结束本轮，不未经用户要求连续吞掉多个大任务。内部检查由Agent承担，不把编译/查日志等默认转给用户。
6. **接收验收**：用户反馈进入下一轮后，先登记验收结论/问题，再按接续规则修复或执行下一小任务。不得让用户再次解释项目背景。

## 用户短指令的固定含义

| 用户输入 | Agent动作 |
|---|---|
| 继续下一步 / 开始下一步 / 下一步 | 读取NEXT_AGENT。若上一步检查通过且无未解决的必要人工项，立即执行唯一下一小任务；有未完成checkpoint则先接续原小任务 |
| 验收通过，继续下一步 | 记录用户对上次明确列出的人工检查通过，再执行下一小任务；不得扩大成所有延期项通过 |
| 有问题 / 贴出报错或异常截图 | 先诊断并修复当前小任务，再按同一模板重新交付，不直接进入下一任务 |
| 暂停 / 换Agent | 保存本任务checkpoint、失败项和精确接续步骤，更新NEXT_AGENT，停止工作 |

若上一交付明确要求用户完成具体点击/观察检查，用户完成后只回复“继续下一步”，可记录为用户对那些已列明检查的确认；仅记录用户确认，不能捏造测量数值或日志。若确实必须提供数值/输出而尚未收到，只追问缺的那一项，先做不依赖它的工作。对未来打印、未列出的核验、未完成的自动测试，“继续”不代表通过。用户未回答不能当作验收。

无人工操作的小任务：交付写“你现在无需操作，回复继续下一步即可”。无需为核心算法强造CAD手工验收。代码检查失败/实质阻塞时不得标完成或要求用户盲目验收。

## 固定交付模板（每次必用，空项写无）

- **本次完成**：小任务编号；用户能理解的变化；交付文件/入口链接。
- **检查结果**：通过了什么、未做什么；当前提交号；本任务是否已合并/备份，按实际说明。
- **你现在做什么**：无需操作，或逐条给出完整路径、打开入口、可用命令、具体操作；不能让用户运行尚未实现的命令。
- **怎样算通过**：每个操作对应可观察的结果；必须带实际测量时说明要反馈什么。没有人工项则写“自动检查通过，无需人工验收”。
- **有问题怎么办**：在哪一步停止、保留什么、反馈哪段错误/哪个画面；不要求修改安全设置或覆盖原图来尝试。
- **未完成/阻塞**：影响、已尝试操作；延期项目明确保留，不能反复拉回抢占已授权主线。
- **下一步**：唯一下一小任务、Agent要做什么、用户是否还需提供资料；给出适用的一行回复，如“继续下一步”。

报告以事实为主，普通步骤简短，人工步骤具体；省额度不等于省掉关键验证。只有新增变更、失败或未解决问题才扩大测试，不重复跑已通过的无关检查。

## 何时讨论，何时直接做

直接做：既定范围内模块实现、修复、必要测试、已授权标准和模板配置、文档同步、小任务接续。已确认的选择不反复申请许可。

先讨论：改变产品范围/验收目标、共享协议、模块依赖或技术栈；与既定业务规则冲突的重大调整；确实需要用户选择且无法由上下文确定的事项。先写清问题、影响、推荐方案，再问一个具体问题。用户已经明确授权的变更直接落实并记录，不再重复确认。

不降低AutoCAD安全设置，不擅自改原始业务文件；无法安全继续时明确原因和替代路径。用户没有新增需求时，不每轮再写长规划。

## 跨Agent、分支和状态

NEXT_AGENT必须包含：当前阶段/小任务及状态、工作分支与基线、完成证据、待用户动作/验收结论、已知失败/延期项、唯一下一小任务的范围和验收点、恢复命令/文件入口。提交前更新，下一Agent以文件接续而非依赖聊天记忆；只在同一仓库或同步后的副本中保证文件可用，本机local证据不假定其他电脑存在。

阶段状态沿用待开始/进行中/阻塞/待验收/完成。小任务完成不等于整个阶段完成；用户交付确认也不能替代缺失的技术证据。

默认从已验收main开任务分支；当前T07获准依赖未合main的T06已提交基础串行开发，须记录依赖。后续分支继承未验收提交时，不得直接合main带入这些提交；等祖先依赖验收后按顺序集成，或先制定不丢失工作的集成方案。验收通过的小任务正常提交，阶段整体满足条件才合main；阶段验收后标签/推送。

额度不足或中断：先保存本任务未完成改动为checkpoint（确有改动才提交），列失败项、精确下一动作、已有证据位置，更新NEXT_AGENT再结束；不称整体完成、不自动合并。用户无需重新整理交接材料。
